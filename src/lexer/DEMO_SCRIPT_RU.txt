КОРОТКИЙ СЦЕНАРИЙ LIVE DEMO

1. Наша конфигурация: Project D, Java, hand-written parser, interpreter.
Сейчас готов первый программный компонент - hand-written lexer.

2. На вход Lexer получает обычную Java-строку с исходным кодом Project D.
Метод scanTokens проходит по ней слева направо. Для каждого распознанного фрагмента
он создаёт Token. Token хранит тип, исходную лексему, значение, строку и столбец.

3. Ключевые слова хранятся в таблице KEYWORDS. Поэтому слово var получает тип
KW_VAR, а придуманное программистом имя total получает тип IDENT.

4. Для операторов применяется longest match. Например, двоеточие и знак равенства
распознаются вместе как ASSIGN, а два символа точки - как RANGE.

5. Запускаем простой пример:
./run_demo.sh examples/01_simple.d

В строке var total := 12.5 лексер распознаёт KW_VAR, IDENT, ASSIGN и REAL.
Лексер ничего не вычисляет. Он только подготавливает поток токенов для парсера.

6. Запускаем пример со слайда 6:
./run_demo.sh examples/02_calculator.d

Здесь видно, что func становится KW_FUNC, => становится FAT_ARROW,
а calculator.operations.add разбивается на идентификаторы и точки.

7. Запускаем пример со слайда 7:
./run_demo.sh examples/03_nested_values.d

Квадратные скобки становятся LBRACKET и RBRACKET. Вызов функции, доступ через точку
и индекс массива пока остаются плоской последовательностью токенов. Их структуру
позже распознает parser.

8. Пробелы, табуляции и комментарии // лексер пропускает. Перевод строки сохраняется
как NEWLINE, потому что в Project D он может разделять statements. При неизвестном
символе или незакрытой строке лексер сообщает позицию ошибки.

ВОЗМОЖНЫЕ ВОПРОСЫ

Почему hand-written?
Мы сами написали алгоритм посимвольного сканирования на Java и не используем
генератор лексеров.

Чем lexeme отличается от token?
Lexeme - конкретный текст, например 12.5. Token содержит категорию REAL,
значение 12.5 и позицию в файле.

Понимает ли lexer вложенные массивы или вызовы функций?
Нет. Lexer выдаёт плоский поток токенов. Вложенную структуру позже строит parser.

Почему NEWLINE не пропускается?
В спецификации Project D statements разделяются точкой с запятой или переводом строки.

Что ещё не реализовано?
Parser, AST, semantic analysis и interpreter относятся к следующим этапам курса.
